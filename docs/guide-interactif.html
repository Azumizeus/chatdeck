🧠 Les 3 agents — activés par le bouton 🧠 ou ⌘K « agents »

🧠 Nexus écrit & orchestre

Orchestrateur multidisciplinaire — architecte logiciel, sécurité, données, produit.

Écrit le brief dans NOTES.md, crée les fichiers, exécute les commandes, puis délègue à Seeker ou PromptDeck quand c'est utile. Seul agent (avec PromptDeck) à pouvoir écrire et committer.

Exemple d'utilisation 
Activer : bouton 🧠 Agents (ou sélecteur « 🧠 Nexus + 🔎 Seeker »)

Toi : « Crée une API Express minimale dans src/server.js
        avec un endpoint /health, puis committe. »

Nexus : écrit src/server.js → vérifie avec run_command
        (node -v, ls) → git_commit "Add minimal Express API"
        → résume ce qu'il a écrit.

🔎 Seeker lecture & analyse

Exploratrice — recherche, analyse, hypothèses testables.

Lecture seule (pas de write_file) : elle explore la sandbox (ls, cat, search), croise les informations et rédige ses conclusions — dans le fil ou dans un fichier si Nexus le lui demande via délégation.

Exemple d'utilisation 
Délegation typique (Nexus décide) :
  Nexus → delegate_to_seeker
          task: "Analyse package.json et src/ :
                 dépendances obsolètes ? risques ?"
  Seeker : ls → cat → rapport
  Nexus  : reçoit report_to_nexus et conclut

À la main : sélecteur « Nexus + Seeker » puis
« Liste les fichiers et résume l'architecture ».

🃏 PromptDeck prompts & collab

Stratège prompts issu du MEGA PACK (190 agents, 133 skills). Peut écrire + déléguer vers Nexus.

Conçoit/améliore les prompts système, décompose les tâches complexes, propose personas & skills. En mode collab il travaille EN PARALLÈLE avec Nexus dans le MÊME workspace : fichiers préfixés deck-, lit les nexus-.

Exemple d'utilisation 
Collab : sélecteur « 🧠 Nexus + 🃏 PromptDeck (collab) »

Toi : « Concevez ensemble le prompt système d'un
       agent de support client, puis écrivez-le. »

Nexus  → nexus-brief.md (besoin, contraintes)
PromptDeck → deck-prompts.md (prompt conçu,
       personas, skills retenus) en parallèle
       → si besoin delegate_to_nexus pour
       l'implémentation, puis report_to_deck.

🛡 AEGIS-7 fiche .CD — .cd/agents/aegis-7.cd

Équipe élite de 7 agents senior en un seul (Archo, Backy, Fronty, Testa, Secu, Opsy, Data) — officiellement documentée dans la fiche aegis-7.cd.

Fiche kind: agent avec triggers (« AEGIS ») : citée dans un message, elle est injectée dans le prompt et le modèle l'incarne avec SA méthode (explorer avant de proposer, utiliser web_search/web_fetch, écrire le réel, git_commit).

Exemple d'utilisation 
Toi : « AEGIS-7 : construis une page dashboard
       avec les prix du bitcoin en direct »

AEGIS-7 : Archo planifie → web_search "bitcoin price api"
  → web_fetch la doc de l'API → Fronty écrit index.html
  (preview prête) → Testa vérifie → git_commit.
🧭 Délégation bidirectionnelle : Nexus ⇄ Seeker et Nexus ⇄ PromptDeck, rapport garanti (report_to_*) injecté dans le fil d'origine — plafonné à 6 sauts. Le rapport apparaît comme « (X a rendu son rapport à Y) ».

🧰 Outils sandbox — agents actifs, agissent sur ~/.chatdeck/workspaces/<conv>

list_tree tous

Liste l'arborescence de la sandbox (fichiers + dossiers).

Exemple
Toi : « Montre-moi la structure du workspace »
Agent → list_tree() → arbre complet dans le fil

read_file tous

Lit le contenu d'un fichier de la sandbox.

Exemple
Toi : « Que contient NOTES.md ? »
Agent → read_file path:"NOTES.md"

write_file Nexus · Deck

Écrit/écrase un fichier (dossiers parents créés). Seeker n'y a pas droit.

Exemple
Toi : « Écris src/utils/date.js avec fmt(iso) »
Agent → write_file path:"src/utils/date.js"
        content:"export const fmt = …"

run_command tous

Commandes en liste blanche : ls, cat, pwd, node -v, npm -v. (Le terminal ⌨︎, lui, exécute node/npm/npx/git… en vrai.)

Exemple
Toi : « Vérifie la version de node dispo »
Agent → run_command cmd:"node -v"

web_search tous

Recherche web SANS URL : interroge DuckDuckGo et renvoie 10 résultats (titre + URL + extrait). L'outil à appeler dès qu'on demande de « chercher sur internet » — puis web_fetch sur un résultat. L'agent ne doit JAMAIS répondre qu'il n'a pas de navigateur.

Exemple
Toi : « Cherche les nouveautés de Svelte 5 »
Agent → web_search query:"svelte 5 nouveautés"
        → 10 résultats → web_fetch url:"…"
        → résume avec les sources

web_fetch tous

Télécharge une page http(s) et renvoie son texte brut (200 ko max) — documenter, vérifier une API, citer une source. Typiquement APRÈS web_search. Chaque page lue est mise en cache (Connecteurs → 🌐 Web).

Exemple
Toi : « Cite la doc officielle de Svelte 5 runes »
Agent → web_fetch url:"https://svelte.dev/docs/svelte"
        → résume + cite l'URL

git_commit Nexus · Deck

git add + commit de TOUT le workspace (endpoint sécurisé, branche par défaut). Visible ensuite dans 📁 Fichiers → Arbre Git avec diff par commit.

Exemple
Toi : « Sauvegarde ce state dans git »
Agent → git_commit message:"Add deck state module"
Puis 📁 Fichiers → 🕘 Arbre Git → clic sur le
commit → diff +/− du fichier.

switch_os tous

Bascule la sandbox vers mac / windows / linux — purge les fichiers platform/ de l'ancien profil. Aussi dispo à la main (📁 Fichiers → switcher d'OS).

Exemple
Toi : « Prépare la sandbox pour un build Windows »
Agent → switch_os os:"windows"
Retour à mac : les fichiers de chaque profil
sont retrouvés intacts.

delegate_to_* Nexus→S·D · Deck→N

Délègue une sous-tâche (Seeker = exploration, Deck = prompts, Nexus = code/ architecture). L'agent cible travaille puis rend son rapport.

Exemple
Automatique : Nexus juge la tâche et délègue.
Forcé : « Demande à Seeker d'analyser les
imports de src/ et de te faire un rapport. »
→ delegate_to_seeker → rapport dans le fil.

report_to_* S→N · D→N · N→D

Outil de clôture d'une délégation : l'agent qui a travaillé rend son rapport (découvertes, fichiers produits). Le message « (X a rendu son rapport à Y) » apparaît dans le fil d'origine.

Exemple
Seeker finit son exploration →
report_to_nexus report:"3 doublons détectés
dans src/utils, voir notes/analyse.md"

📦 Outils projet — conversation rattachée à un projet (sidebar ▸ Projets)

write_project_file tous

Écrit dans le workspace PARTAGÉ du projet (~/.chatdeck/workspaces/p-<id>) — visible par toutes les conversations du projet. Chaque écriture demande confirmation.

Exemple
Toi : « Pose ce README dans le projet »
Agent → write_project_file path:"docs/README.md"

read_project_file tous

Lit le workspace projet, sinon les dossiers Mac autorisés par l'utilisateur (LECTURE SEULE — ex. ~/projects/chatdeck).

Exemple
Toi : « Lis vite.config.ts du vrai projet »
Agent → read_project_file path:"vite.config.ts"

list_project_tree tous

Liste l'arborescence du projet + les dossiers Mac autorisés.

Exemple
Toi : « Que vois-tu du projet et du Mac ? »
Agent → list_project_tree()
🔐 Dossiers Mac : ▸ Projets → projet → « Dossiers autorisés ». Les agents y lisent, jamais n'écrivent ; toute écriture passe par la confirmation (gate de permission 🔐 dans le fil).

🃏 Skills & bibliothèque PromptDeck — 636 fiches FR/EN

deck_search tous

Cherche la méthode/persona adapté dans la bibliothèque (recherche bilingue) AVANT d'inventer une méthode.

Exemple
Toi : « Fais une revue de code rigoureuse »
Agent → deck_search query:"revue de code"
→ liste les fiches (id + résumé + score)

deck_load tous

Charge une fiche par son id — elle devient LA méthode à appliquer jusqu'au bout.

Exemple
Agent → deck_load id:"verification-lot"
→ applique le protocole de vérification
  de la fiche à la tâche en cours.

promptdeck_browse PromptDeck

Explore l'arborescence complète du MEGA PACK (agents + skills) pour choisir personas et skills.

Exemple
Toi (à PromptDeck) : « Quel persona pour un
  agent de veille concurrentielle ? »
→ promptdeck_browse() puis recommandation

Fiches .CD (activation) UI

Markdown + frontmatter (name, description, kind: skill|agent, tools, triggers:). 3 sources : pack (lecture seule), ./.cd/ (projet, éditable dans le panneau), ~/.chatdeck/ (global).

Exemple 
🃏 Skills & Agents (hub) → clic = active la fiche
   (globale) ; pastille 🃏 du composer = activation
   POUR CE FIL. Plafond 12 fiches actives.
Créer : bouton créer du panneau (ou CLI :
   deck cd --new ma-methode), remplir le
   frontmatter, utiliser au prochain tour.
Microagents : triggers: "revue,audit" déclenche
   la fiche quand ces mots apparaissent.

CLI deck terminal

Le même moteur en ligne de commande : deck search, deck ask, deck run (agent avec outils, confirmations), deck doctor.

Exemple
deck search "revue de code"
deck run "Corrige le test qui échoue"   # confirme bash/write
deck ask "Pourquoi SSE plutôt que WS ?" --provider nvidia

🔌 Connecteurs & MCP — l'outil unique connector_call

connector_call tous

Interroge les connecteurs : 5 intégrés (workspace tree|file, deck search, horloge now, web historique/favoris/cache, browser-use via MCP) + HTTP déclarés dans ⚙︎ Réglages (la clé reste sur la machine).

Exemple
Toi : « Quelle heure est-il, au fait ? »
Agent → connector_call connector:"horloge" op:"now"
HTTP : « Liste les repos publiques de l'API
  GitHub que j'ai branchée » → connector_call
  connector:"github" op:"/repos/owner/name"

Serveurs MCP stdio tous

Déclarés dans ~/.chatdeck/mcp-servers.local.json — leurs tools sont exposés via connector_call (op: tools|call). Ex. cognee : remember, recall, cognify_file… (11 outils).

Exemple
{"name":"cognee","command":"npx",
 "args":["-y","cognitive-backend","stdio"]}

Panneau 🔌 Connecteurs liste les tools détectés.
Toi : « Retiens que je préfère les réponses
  concises » → l'agent appelle l'outil
  remember du serveur cognee.

browser-use (MCP) tous

Contrôle du VRAI Chrome : browser_navigate, browser_click, browser_type, browser_screenshot, browser_get_state… (16 outils). Installé via venv + --mcp — le panneau 🔌 Connecteurs affiche ses outils détectés.

Exemple
{"name":"browser-use","command":
 "/…/browser-use-venv/bin/browser-use","args":["--mcp"]}

Toi : « Ouvre example.com et fais une capture »
Agent → connector_call connector:"mcp:browser-use"
  op:"call" path:"browser_navigate"
  → puis browser_screenshot

🌐 Web (mémoire) connecteur

Mémoire automatique des accès web : chaque web_search alimente l'historique, chaque page web_fetch est mise en cache (10 ko), favoris gérables (★). Visible dans 🔌 Connecteurs → 🌐 Web, stocké dans ~/.chatdeck/web.local.json.

Exemple
🔌 Connecteurs → 🌐 Web →
  ⭐ Favoris · 🕘 Dernières recherches · 📄 Pages en cache
(clic ★ pour épingler une page en favori)

⚔︎ Duel & collaboration

⚔︎ Duel ⌘K « duel »

Deux conversations côte à côte, streaming concurrent, bouton ⇉ = même message aux deux. Arbitre : ⚖︎ Synthèse (ou débat 2 tours) tranche « Verdict : A / B / égalité ». Sortie : le bouton ⚔️ Quitter le duel présent DANS chaque colonne (ou « ✕ quitter le duel » en verdictbar) — le même bouton redevient « Duel » pour y retourner.

Exemple
⌘K → « duel » → ⇉ « Explique les runes Svelte 5 »
→ compare → ⚖︎ Synthèse → verdict affiché.

🃏 Collab verdictbar duel

Nexus + PromptDeck en parallèle, workspace partagé (préfixes nexus- / deck-). Bootstrap garanti du workspace hôte.

Exemple
Duel ouvert → 🃏 Collab → « Rédigez le cahier
des charges de la v2 » → chacun écrit ses
fichiers, se mentionnent, rapport final.
